You are reviewing heart_cam, an ESP32-S3 firmware that measures heart rate (rPPG, POS
algorithm) and breathing rate (1-D Lucas-Kanade on luminance profiles) from a camera,
plus a Python viewer. It is aimed at becoming a contactless baby/sleep monitor, so a
WRONG READING IS WORSE THAN NO READING. Two previous reviews have been done and their
fixes have landed; this is the third pass.

Read the code yourself. Key files: idf/main/main.cpp (tasks, camera, zoom, ROIs),
idf/main/rppg.cpp/hpp (heart rate), idf/main/resp.cpp/hpp (breathing + new presence
detection), idf/main/motion.cpp/hpp (tile tracker), idf/main/tracker.hpp (shared Kalman,
octave resolution), idf/main/evm.cpp/hpp (Eulerian magnification, off by default),
heartcam.py (viewer), idf/test/*.cpp (host tests), tools/*.py. NOTES_FOR_MORNING.md
records what the previous two reviews found and what was done about each.

Focus, in priority order:

1. NEW CODE SINCE THE LAST REVIEW, reviewed hardest:
   - resp.cpp check_presence(): breathing PRESENCE (is anything breathing right now),
     deliberately separate from rate. Is the floor estimate (quietest quartile of recent
     swing) sound? What is its actual detection latency when breathing STOPS? What
